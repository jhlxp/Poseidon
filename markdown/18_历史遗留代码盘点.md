# 历史遗留代码盘点

## 1. 盘点口径

本文档记录 2026-08-10 对当前 `main` 的静态调用链、构建入口和测试引用
检查。“当前没有消费者”不等于可以无条件删除；本盘点把代码分为：

- 小型、无消费者的删除候选；
- 当前仍可达，但名称或产品边界过时的兼容代码；
- 看起来像历史遗留，实际仍被 MpRail/测试使用的代码。

本轮已清理第 2 节的小型无消费者；其余兼容与产品边界代码未动。

## 3. 应重命名或收口，但不能直接删除

### 3.1 `OxcDagManager` 是活动 DAG 执行器

`htsim/sim/datacenter/oxc_dag_manager.{h,cpp}` 的命名来自旧 OXC 阶段，但
`main_uec.cpp` 在静态 `.dag` 和动态 `-dag_control` 两条路径上都直接实例化
`OxcDagManager`。ProbeEP 的单进程动态 append/observation 也由它完成。

正确处理是独立重命名为拓扑无关的 `DagManager`/`DagTask`，同步修改
include、CMake 和日志名。直接删除会让 MpRail 的静态 DAG 和 ProbeEP 动态 DAG
全部失效。

### 3.2 静态 ProbeEP 是兼容功能，不是有效性能路径

`generate_moe_dag.py`、Transformer builder 和
`run_dsv3_2layer_algorithms.py` 仍支持一次性生成静态 ProbeEP。它对 task 结构、字节、
可视化和 emitter 回归有价值，但没有消费前一个 observation 的实测 FCT。

短期保留并在所有文档标注“仅结构回归”。若后续要收紧 API，应将它改为显式
`--static-probe-functional` 之类的入口，并让默认静态算法列表只包含
NCCL/DeepEP/EPLB/MoonEP。

### 3.3 通用 CPU stream 代码当前无算法消费者

`pysrc/moe_dag/models/streams.py` 仍能处理 `logical_resource=cpu`，但当前五个
算法都必须报告 `cpu_task_count=0` 和 `cpu_streams_global=0`。ProbeEP planner 是离线
Python 决策，不应通过 CPU lane 回到 DAG。

这段属于未来 host task 兼容层，不是死分支。只有项目明确不再支持任何
host-side task 时，才应连同 manifest 字段和测试一起删除。

### 3.4 根 `README.md` 是上游文档

仓库根 `README.md` 仍以 SPCL HTSim、Dragonfly 和 SlimFly 为主，没有把
Poseidon/MpRail/workload generator 作为第一入口。它是文档债，不是死代码。
建议后续改成项目 README，并把上游说明移到单独的 provenance 章节。

## 4. OXC/OCS 产品边界遗留

`htsim/sim/datacenter/oxc*` 共 15 个被跟踪文件、4,637 行，包括：

- DAG manager 2 个文件、821 行，当前 MpRail 仍在使用；
- OXC topology/switch/OCS graph/spraypoint/KSP 及三个 dump 程序 13 个文件、3,816 行。

第二组对当前 MpRail-only 产品方向是历史功能，但它们仍在
`htsim/sim/datacenter/CMakeLists.txt` 中编译，`main_uec.cpp` 也仍保留 OXC 配置、
拓扑构建和路由分支。因此它们是“产品范围外但技术上仍可达”，不是
编译器意义上的 dead code。

若决定彻底去掉 OXC，应先抽离/重命名 DAG manager，再一次性删除 OXC CLI
参数、`main_uec.cpp` 分支、CMake source/dump targets 和 13 个 OXC 拓扑文件。
不应只删文件留下不可达选项。

## 5. 看起来旧，但当前仍在使用

| 代码/产物 | 当前用途 | 结论 |
|---|---|---|
| `server_forward` CM/DAG route | 显式 `src_local -> fabric -> dst_local` 通用转发，有独立源路由测试 | 不能删；五个 MoE builder 不使用它不代表公共路由功能无用 |
| `output_metrics/` | 仅在 `HTSIM_LINK_LOAD_SAMPLE=1` 时由 link-load sampler 生成，完整实验的 PNG/CSV 直接消费 | 不能删；未启用 sampler 时不应生成 |
| `LoggedManager::dump_idmap` | `main_uec`/MpRail 已不调用，但 Dragonfly、SlimFly 和其他上游 binary 仍调用 | MpRail 路径不恢复 `idmap.txt`；若删上游 binary 再一并收口 |
| `H100CostModel` | 无 JSON 的 smoke 默认模型，且被 workload 测试广泛使用 | 不能因完整实验默认 H20 而删除 |
| `gate.py` 与 `load_profile.py` | 前者生成 Gate assignments，后者构造算法 before/after execution placement | 职责不同，不是重复代码 |
| FatTree/Dragonfly/SlimFly 上游代码 | 仍有构建 target、脚本或入口 | 是 vendored 产品面，是否删除需要先决定仓库范围 |

## 6. 建议清理顺序

1. 将 `OxcDagManager/OxcDagTask` 重命名为拓扑无关名称，运行静态 DAG、
   `run_dynamic_dag_functional.py` 和 ProbeEP 2-token 动态 smoke。
2. 决定是否从产品面删除 OXC、FatTree、Dragonfly 或 SlimFly；这是范围决策，
   不应与无调用 helper 的小清理混在同一个提交。
3. 最后收紧静态 ProbeEP 和 CPU stream 兼容 API，这会改变外部调用契约，需要
   先明确迁移方案。
